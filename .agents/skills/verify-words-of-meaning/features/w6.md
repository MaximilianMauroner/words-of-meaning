Preserve the Markdown journey's intended result: a task with
`outputFormat: "markdown"` must produce an actual Markdown artifact that matches
its brief. Inspect the exported manifest and file contents; a completed task
status or successful create response cannot prove this. The fake worker currently
writes `App.tsx` and `styles.css` for every format except `plain_html_css`, and
the scheduler validates only plain-HTML artifacts. Therefore this procedure's
fake-mode Markdown coverage is **blocked by the implementation**. The runner
owner must repair fake generation and format validation before this portion
can pass. Track [issue #6](https://github.com/MaximilianMauroner/words-of-meaning/issues/6)
for this repair. Real-provider output requires [W7](w7.md)'s separate authority.

The current schema accepts `judges` and each judge's `channels`, but
`createExperiment()` does not consume `input.judges`. It inserts one judgment
per generation, and the scheduler uses the experiment's single judge with
the canonical source bundle. There is no screenshot-channel dispatch or
separate judge/channel result identity. A successful create response does not
prove that these requested options took effect.

Run the available UI task/artifact checks separately and report the multi-judge
and source/screenshot portions **blocked by the implementation**. Do not count
schema/domain tests, fake output or duplicated single-judge results as those
acceptance checks. Preserve the expected outcome: each configured judge and
channel must produce distinguishable results before cross-judge or channel
coverage can pass. Resume that part after a reviewed product repair; this
procedure change does not implement it.
