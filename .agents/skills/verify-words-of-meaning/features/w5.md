# W5

| ID | Public actions and expected result | Source / supporting tests | Reset |
| --- | --- | --- | --- |
| W5 | Verify cancellation and restart recovery with two separate owned delayed fake experiments. Cancellation prevents more dispatch; an uncanceled interrupted job retries with a new isolation identity and retains its old attempt. | cancel route, scheduler; scheduler integration and isolation tests | Wait for child exits before state deletion. |

Use the core's owned fake-worker instance and database. Add
`WORDS_FAKE_DELAY_MS=30000` to its launcher so a running attempt can be
observed before it finishes. Keep global and per-experiment concurrency at
one. Read each created ID from the public response and retain separate IDs
for these two cases.

1. **Cancellation:** create an experiment and wait until an attempt is running.
   POST `/api/experiments/:id/cancel` for that ID. Confirm the response reports
   `canceled: true`, the experiment reports `cancel_requested: 1` and
   `status: "canceled"`, and jobs pending at cancellation are canceled. The
   cancellation flag prevents later dispatch even if an aborted job returns
   to pending. Wait for the owned
   worker to exit and inspect its attempt error. An aborted call can report
   `Model call canceled`; do not expect restart interruption or a retry from
   this experiment. After the recovery-case restart below, confirm that the
   canceled experiment has no new attempts.
2. **Restart recovery:** create a different experiment and confirm it is
   uncanceled with a running job and an unfinished attempt. Retain that
   attempt's `job_id`, `ordinal`, `process_id` and exported `isolation_id`.
   Stop the owned server first, then any surviving owned worker children,
   without calling the cancel endpoint for this experiment. Preserve its
   SQLite database. Restart the same instance against that database and
   recheck preflight. The old attempt must report
   `Interrupted by process restart`; the same job must gain a later attempt
   with a larger ordinal and a different process and isolation identity.
   Inspect `/api/experiments/:id/export` for both attempts. After recording
   recovery, cancel remaining owned work and wait for all child exits before
   the core's state cleanup.

If the initial attempt finishes before the interruption, the setup did not
exercise recovery. Reset only the owned fixture and record the unrun case;
do not relabel a completed or canceled call as a restart pass.
